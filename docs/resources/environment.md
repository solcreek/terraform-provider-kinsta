# kinsta_environment (Resource)

Manages a staging environment of a WordPress site. A site's live environment is created with the site and cannot be managed (or deleted) through this resource.

## Example Usage

```terraform
resource "kinsta_environment" "staging" {
  site_id      = kinsta_site.blog.id
  display_name = "Staging"
  install_mode = "plain"
}
```

## Creation-only arguments

`install_mode`, `admin_email`, `admin_user`, `admin_password`, `site_title`, `wp_language`,
`is_multisite`, `is_subdomain_multisite`, `woocommerce` and `wordpressseo` are sent only when
the resource is created. Kinsta does not return them, so they are not compared with the live
installation: changing one later updates the value in state (with a warning) and changes
nothing in WordPress, and an imported resource does not need them at all.

`admin_password` is stored in state (marked sensitive). Change the password in WordPress
after creation if your state is shared.

## Deleting

`deletion_protection` defaults to `true`. With it set, destroying the resource — or a change
that would replace it — fails before anything is deleted. To delete on purpose, back the
site up, set `deletion_protection = false`, apply, and then destroy.

## Schema

### Required

- `display_name` (String) Environment display name, e.g. `Staging`. Changing it replaces the environment.
- `site_id` (String) ID of the site to add the environment to.

### Optional

- `admin_email` (String) WordPress admin email. Required for `install_mode = "new"`. Only used when the environment is created; see *Creation-only arguments*.
- `admin_password` (String, Sensitive) WordPress admin password. Required for `install_mode = "new"`. Stored in state (marked sensitive); change it in WordPress afterwards if state is shared. Only used when the environment is created; see *Creation-only arguments*.
- `admin_user` (String) WordPress admin username. Required for `install_mode = "new"`. Only used when the environment is created; see *Creation-only arguments*.
- `deletion_protection` (Boolean) Refuse to delete the environment. Defaults to `true`, because deleting an environment removes its files and database. Set it to `false` and apply before destroying it.
- `install_mode` (String) `new` (default) installs WordPress with the admin user below. `plain` creates an empty environment without WordPress, for content deployed by other means; the admin and WordPress arguments are then ignored. Only used when the environment is created; see *Creation-only arguments*.
- `is_multisite` (Boolean) Install WordPress Multisite. Only used when the environment is created; see *Creation-only arguments*.
- `is_premium` (Boolean) Create a premium staging environment (billed separately). Defaults to `false`. Changing it replaces the environment.
- `is_subdomain_multisite` (Boolean) Use subdomains rather than subdirectories for Multisite. Only used when the environment is created; see *Creation-only arguments*.
- `site_title` (String) WordPress site title. Required for `install_mode = "new"`. Only used when the environment is created; see *Creation-only arguments*.
- `woocommerce` (Boolean) Install WooCommerce. Only used when the environment is created; see *Creation-only arguments*.
- `wordpressseo` (Boolean) Install Yoast SEO. Only used when the environment is created; see *Creation-only arguments*.
- `wp_language` (String) WordPress locale, e.g. `en_US` (the default when unset). Only used when the environment is created; see *Creation-only arguments*.

### Read-Only

- `id` (String) Environment ID.
- `name` (String) Environment name Kinsta derives from the display name.
- `php_version` (String) PHP version the environment runs, e.g. `8.3`.
- `primary_domain` (String) Primary domain of the environment.
- `web_root` (String) Path of the environment's web root on the server.

## Import

Import is supported using the following syntax:

```shell
# Import by <site_id>/<environment_id>.
terraform import kinsta_environment.staging 0f7a3e1c-0000-4000-8000-000000000000/7d2b9c44-0000-4000-8000-000000000000
```
